Watching grpc-pdf-inspector route a PDF

One HTTP request carries the PDF up while events come back down, the same shape as the gRPC call underneath. A PDF's cross-reference table is its last bytes, so nothing can begin until the upload bar fills — then info, the classification, arrives in tens of milliseconds, long before any page is extracted. That event is the routing answer: text-based documents stream their markdown page by page; scanned and image pages are named in pages_needing_ocr so a caller can send only those to a heavy OCR path. This server never OCRs.

The upload throttle delays the upload only; the event pace delays how fast rows are drawn, by pausing the gRPC stream between events. Neither changes what the server does. Try scanned-image.pdf against hello-text.pdf: the classification arrives just as fast for both, but the scanned document has no text layer, so instead of page markdown its info names every page in pages_needing_ocr — that list is the whole point of the service. mixed.pdf shows both at once. Detect mode stops after the classification: no page is ever extracted.
